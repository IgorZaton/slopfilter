# Session Guardrails

Apply these always:

1. Think before coding — state assumptions; clarify ambiguity.
2. Goal-driven — verifiable success criteria; verify each step.
3. Surgical changes — touch only request-scoped files/lines.
4. Simplicity first — no speculative features or abstractions.
5. Conventional Commits for suggested commit/PR titles.
6. Never commit secrets; never update git config; never skip hooks unless asked.
7. Prefer small staged delivery with checks between stages.
